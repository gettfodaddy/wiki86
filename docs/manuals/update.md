# Обновление Remnawave



**Раздел:** remnawave  

**Адрес:** /manual/remnawave/update



Обновите Panel и ноды в безопасном порядке, сохраните резервную копию и проверьте состояние сервисов.



## Твои данные

Заполни поля в форме на сайте: их значения подставляются в примеры по всей инструкции. Примеры ниже показывают поля и подсказки.

| Переменная | Поле | Пример | Подсказка |
| --- | --- | --- | --- |
| PANEL_DIR | Каталог Panel | /opt/remnawave | Путь к Compose-файлу панели. |
| NODE_DIR | Каталог Node | /opt/remnanode | Путь к Compose-файлу ноды. |

## Перед обновлением

• Проверьте [официальный changelog Remnawave](https://github.com/remnawave/panel/releases) и прочитайте примечания к версии: для отдельных релизов могут быть дополнительные действия.

• Сохраните резервную копию базы данных панели, а также файлов `.env` и `docker-compose.yml`.

• Обновляйте панель первой, затем ноды — по одной ноде за раз.

Официальная инструкция: [Remnawave Upgrading](https://docs.rw/install/upgrading/).

## 1. Обновление панели

Выполните на сервере панели:

```bash
cd {{PANEL_DIR}}
docker compose pull
docker compose down
docker compose up -d
docker compose logs -f
```

Дождитесь запуска контейнеров и проверьте логи. Чтобы выйти из просмотра логов, нажмите `Ctrl+C`. Это остановит только просмотр логов.

Проверьте состояние контейнеров:

```bash
docker compose ps
```

## 2. Обновление нод

На каждом сервере с установленной нодой выполняйте команды отдельно. В вашей установке каталог Remnawave Node — `{{NODE_DIR}}`. Переходите к следующей ноде после проверки предыдущей:

```bash
cd {{NODE_DIR}}
docker compose pull
docker compose down
docker compose up -d
docker compose logs -f
```

Дождитесь запуска и проверьте статус контейнера:

```bash
docker compose ps
```

Проверьте логи Xray внутри контейнера Remnawave Node:

```bash
docker exec remnanode xlogs
```

Остановить просмотр логов можно нажатием `Ctrl+C`.

## 3. Завершение

После обновления всех нод откройте панель и проверьте, что ноды подключены. Если changelog установленной версии требует принудительного перезапуска нод, выполните это действие в панели: **Nodes → Management**.

## Важно

• Команда `docker compose down` останавливает и удаляет контейнеры Compose, но сохраняет данные в Docker volumes.

• Не добавляйте `-v` к `docker compose down`: этот флаг удаляет volumes.

• Во время перезапуска конкретной ноды её активные VPN-соединения прервутся. Поэтому обновляйте ноды по очереди.

• Не заменяйте `.env` и `docker-compose.yml` файлами из новой установки: используйте текущие файлы и инструкции из changelog.
